# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev               # dev server at http://localhost:3000
npm run build             # production build (also type-checks)
npm run lint              # next lint (eslint: next/core-web-vitals + next/typescript)
npx tsc --noEmit          # type-check without building
npm run optimize:images   # convert JPG/PNG in public/images and public/paintings to WebP (sharp, quality 85)
npm run showcase:check    # Node checks of the home page's pure modules (Paintwise's exploded still life, the paintings wall), the works, and the generated media
npm run showcase:assets   # rebuild the groups' media (paintwise, paintings, animation; or name one) into public/showcase + each one's *.generated.json; needs Python with torch + torchvision + transformers + opencv-python-headless, ffmpeg, curl, Blender
```

There is no test suite beyond `npm run showcase:check`. Verify changes with it, `npm run build` / `npm run lint`, and by viewing the page in the dev server.

`npm run analyze` sets `ANALYZE=true` but `@next/bundle-analyzer` and `cross-env` are not installed or wired into `next.config.ts`, so it does nothing extra right now.

## Architecture

Personal art × code portfolio: Next.js 15 App Router, React 19, TypeScript (strict), Tailwind CSS v4, CSS modules, shadcn/ui set up (new-york style, `components.json`). Path alias `@/*` → `src/*`.

- **The site is one page (`src/app/page.tsx`):** `<Showcase />`, the hero, followed by the work (see "Home page" below). It's the only route.
- **The old separate pages are retired (2026-11-21).** `/paintings`, `/animation`, `/games`, `/hackathons` and `/paintwise` were deleted with the navbar (`Navigation.tsx`). They are in git history before the cleanup commit, including the Paintwise build log (blog posts) that lived only on `/paintwise`. Every work's story and links now live only in `src/components/showcase/works.ts`.
- **Shared shell:** `src/app/layout.tsx` wraps every page with `Footer` only (`src/components/Footer.tsx`, rebuilt 2026-11-21 for the one-page site: the name and contact marks, links to the home page's sections (`/#paintwise` etc.), and the copyright with "Back to top"). The contact marks are shared with the hero in `src/components/marks.tsx`. There is no navbar. The layout loads fonts (Geist, Geist Mono, Kalam for the picker's handwritten note, and Poppins 800 for the titles, as CSS variables) and mounts Vercel Analytics plus Google Analytics (`NEXT_PUBLIC_GA_ID` env var). The site is dark-only: `dark` class is hardcoded on `<html>`/`<body>`.
- **Styling:** Tailwind v4 config lives in CSS (`src/app/globals.css`, using `@theme inline` and oklch shadcn tokens). There is no `tailwind.config.js` (the README is outdated on this). The showcase is styled with CSS modules: dark ground, cream `#ece4d4` type, Poppins 800 titles. The hero uses Tailwind utilities. Use `cn()` from `src/lib/utils.ts` to merge classes. Add shadcn components into `src/components/ui/` (only `earth-blaze.tsx` is there now; the unused shadcn primitives and their Radix packages were removed).

### Home page: the hero, then the work

The page under the hero was redesigned on 2026-11-03: the 3D room was dropped for plain sections (it is in git history up to `6307a3f`; its specs are marked superseded). Earlier heroes are in git history: the seam hero (seam in the name, spec `2026-11-15-hero-seam-in-name-design.md`) and the hero's other backgrounds (swirls, dawn, wave) until the 2026-11-21 cleanup, the fluid-line hero with the zip before that, and the gallery hero on the `hero-art-x-code` branch.

- **The hero** (`hero/SparklesHero.tsx`): the name, the description (`DESCRIPTION` in `heroConfig.ts`, in sans) and GitHub / LinkedIn / Email links over the repainting.
  - **The repainting** (`showcase/Repainting.tsx`): one of nine paintings is painted again stroke by stroke, coarse to fine.
    - A soft underpainting wash goes down first, then three passes (`PASSES`).
    - The first painting is random, the rest come in a shuffled order, and each crossfades into the next.
    - Its tunables are constants at the top of the file.
  - **The picker** (`hero/PaintingPicker.tsx`, top right): it opens on hover (tap or keys on touch), with a handwritten "Choose the painting" note while it's closed.
  - **Under the hero:** `showcase/WorkDivider.tsx` holds "My Work" and an arrow. They slide down from the hero's bottom with scroll and settle between two lines.
  - **Still in `hero/`, for other parts:** `heroConfig.ts` (the gallery data `works.ts` builds from, and the name's design used by the Paintings title), `nameRaster.ts` and `brushGeometry.ts` (the Paintings title), and `gallery.json` with its generated assets.
- **The work (`src/components/showcase/`):** `Showcase.tsx` is the page. It runs: the hero, the divider, then the sections `paintwise/PaintwiseSection.tsx`, `hackathons/HackathonsSection.tsx`, `paintings/PaintingsSection.tsx`, `games/GamesSection.tsx` and `animation/AnimationSection.tsx` (page order is also `GROUP_ORDER` in `works.ts`). It also has `DetailPanel.tsx` (a work's story, `#work/<slug>`) and `HandOff.tsx` (the pipeline figure full size).
  - **Paintwise:** the pitch beside the pipeline figure, then the old room's two exploded views side by side, wider than the section. One shows the jug's six layers fanned out with their tags. The other shows Childhood Toys (the user's painting) cut into SAM 2.1's pieces, each pushed out to its Depth Anything V2 depth. Each is a CSS 3D stage of its own shape (`paintwise/explode.ts`, pure) that starts as the jug and comes apart once as it scrolls into view. The masks view stands on a faint grid floor (`FLOOR` in `explode.ts`), shown once it's apart. Each rig is fitted to its stage with the browser's own projection maths, so nothing is measured at runtime. No three.js on the page.
  - **Paintwise's background:** `paintwise/PaintToBinary.tsx` (canvas 2D, pixel art): swirling brush strokes in dulled vibrant colours, each turning into 0s and 1s halfway along and dissolving behind the brush, over a dim ground picked by its `GROUND` switch (`underpainting`, `binary` or `weave`; `?ground=` in the URL tries another). Each section's background must differ from the others and from every hero background option.
  - **Hackathons:** a trifold carousel per project.
    - **Panels:** the logo panel leans in on the left, the demo sits in a browser frame in the middle, and the name and blurb lean in on the right. Turning folds the side panels shut and open.
    - **Demos:** live sites load in an iframe at desktop width, scaled. VRShop (a Quest app) plays a loop from its YouTube demo instead.
    - **Focus mode:** clicking a demo enlarges it under the heading with the side panels behind, and locks the page scroll while it's in use.
    - **Per project:** keys hints are set per project (`keys`, ExoVision's). Media is in `public/showcase/hackathons/`.
    - **Demo sizing:** each live site is sized from its panel's layout size (the ResizeObserver's), never `getBoundingClientRect`: the fold and zoom transforms shrink that and left the site too small.
  - **Title and background:** the title scrambles (`ScrambleTitle.tsx`) over very faint falling letters (`RainingLetters.tsx`).
  - **Animation:** the film's programme over a centred screen; under Wild West, its models on drawn stumps and its storyboard on a running film strip. Its title is a hand-drawn line that boils (`animation/HandDrawnTitle.tsx`: a wobbly pencil outline redrawn 8 times a second) over film grain, flicker and scratches (`animation/FilmGrain.tsx`, sticky to the view). The models are drawn by one three.js canvas over the row (`animation/stumpScene.ts`, imported as the section nears): each model into its stump's slot with a scissored viewport and its own fitted camera, so there's one render a frame and no copying between canvases (three `<model-viewer>`s did that, and were the page's slowest part; model-viewer was removed 2026-11-23). It warms up a model at a time while the browser is idle (parse, compile, one draw) before the row is seen. Drag a slot or use its arrow keys to turn a model.
  - **Games:** `games/GamesSection.tsx` (spec `2026-11-21-games-handheld-design.md`). Five jam games sit in one big handheld (`Handheld.tsx`) with their cartridges fanned out above it. Its shell is one charcoal for every game (the user didn't want it changing colour; A and the power light are a fixed purple, `--key`), the cartridge in it is outlined in the game's colour (not faded), and its screen takes the game's own shape at a fixed height (`--glass-h`, from container units), so there are no bars and the page never shifts. Its L and R, d-pad, SELECT, A, B and START work. There's no Full story link in Games. Each game plays in place through itch.io's own embed (`itch.io/embed-upload/<upload id>`; the raw `html-classic.itch.zone` build shows a "use itch.io" banner when framed elsewhere). Murphy's Rocket only downloads, so it plays its YouTube video. Skyball is a `Work` written out in `works.ts`, like VRShop. The whole section is pixel art (2026-11-23): the title (`PixelTitle.tsx`: Pixelify Sans on a stepped block shadow in the coral of Earth Blaze's horizon glow, fixed for every game, its letters dropping in), the handheld and cartridges (stepped-corner clip-paths on a `--p` pixel grid, smooth motion (no stepped timing; the user disliked the low-fps look), flat colours in hard bands, sprite arrows drawn with box-shadows, covers drawn small by `PixelArt.tsx`), the manual's names and labels (Pixelify Sans and Silkscreen, loaded in `layout.tsx` as `--font-pixel` / `--font-pixel-small`, not preloaded; story text stays in Geist), and the background: Earth Blaze, a WebGL Earth horizon from 21st.dev (`src/components/ui/earth-blaze.tsx`, mounted by `games/EarthBackdrop.tsx`: sticky, faded at the section's ends, its light following the mouse anywhere over the section (the section passes pointer moves on to the canvas; no presses, no aurora, no tab stop), with NASA's Blue Marble served from `public/showcase/games/` as WebP). Earth Blaze runs in its pixel mode (`pixelSize` 4: a canvas pixel per 4 CSS px, upscaled with hard edges; `colorLevels` 7: dithered with a 4×4 Bayer matrix in gamma space; stars as single pixels and small plus-shaped sparkles; kept dim: `SKY` in `EarthBackdrop.tsx` turns the nebula, stars, sun and Earth down). It draws at most 60 frames a second (`minFrameMs` 12; lite: 30 moving, 20 still). Never put a CSS mask, opacity or filter over the canvas: with it redrawing every frame, the browser re-blends the whole screen each frame (that halved Games' frame rate on a weak machine). The section's end fades are bands of the page's ground (`#0d0d0d`) laid over it. Only the game on the screen is drawn smooth.
  - **Unused room media:** some media made for the old room is still unused: the salon depth maps and some GLB models (Draco; decoder kept in `public/draco/`).
- **Content:** `works.ts` builds the works from the hero gallery data and adds the stories, links and groups. VRShop isn't in the gallery: it's a `Work` written out in `works.ts`. Paintwise's media (the jug's layers and per-object masks; Childhood Toys cut into pieces by SAM 2.1 large with Paintwise's own segmenter settings (needs `torchvision`; about 3 minutes); the pipeline figure; and still lifes no longer shown) comes from `npm run showcase:assets` (`scripts/showcase/build-assets.py`, sources in `scripts/showcase/sources/`); the figure itself is `scripts/showcase/paintwise-figure.py` + `render-figure.sh`. The paintings and animation media come from the same command: the early works (+ depth) and held photos from `public/paintings`, the film loops and posters cut with ffmpeg from the release (cached in `scripts/showcase/.cache/`, git-ignored), and the models compressed by Blender (`scripts/showcase/compress-glb.py`) from raw GLBs in `scripts/showcase/sources/models/` (git-ignored, 17 MB; without them the committed models are kept). `public/showcase/**` is exempt from Git LFS so the loops ship with the site. The generated JSON lives in `src/components/showcase/stations/<group>/` (the folder name is from the room). Never hand-edit the `*.generated.json` files. Gallery content is `src/components/hero/gallery.json`. After editing it, run `npm run hero:assets`. That runs `scripts/hero/depth.py` (Depth Anything V2 via transformers + torch + Pillow) and `scripts/hero/build-hero-assets.mjs` (sharp + shiki), which write hashed files to `public/hero/` and `gallery.generated.json`. Commit both. Never hand-edit the generated JSON.

### Media and content

- **Paintings:** `public/paintings/manifest.json` (`{ items: [{ src, title, description, year, wallPosition }] }`) lists every painting. The asset scripts read it (`scripts/hero/*` check the gallery against it; `showcase:assets` takes the early works from it). `wallPosition` is `"portfolio"` or `"pre-portfolio"` (Early Work). Some paintings have a "held" photo variant, `<Name>_2.webp`.
- **Images** go in `public/images` or `public/paintings` as `.webp`. Run `npm run optimize:images` after adding JPG/PNG.
- **Image sizes:** `npm run images:sizes` (`scripts/showcase/image-sizes.mjs`; `showcase:assets` and `hero:assets` run it after themselves) writes smaller copies beside the WebPs the page shows with a srcset (`USED` in the script: add a pattern when another `<img>` takes one) (`x.webp` → `x.w320/640/960/1440.webp`, only those well under its width) and lists them in `src/lib/image-sizes.generated.json` (never hand-edit). `<img>`s take them through `responsive(src, sizes)` from `src/lib/images.ts` (srcset + sizes), and canvases through `sized(src, width)`. A decoded image costs its full pixels in memory however small it's shown: this took the page's images from 245 MB decoded to 74 MB. The paintings wall gives the picked painting its full image (the wall zooms in on it). `showcase:check` fails if a listed copy is missing.
- **Videos:** `.mp4` and other video files, plus everything in `public/videos/`, are tracked with **Git LFS** (`.gitattributes`). They're too large to serve from Vercel, so the full films load from the GitHub release `videos-v1.0` (`https://github.com/aayushs-edu/aayushs-portfolio/releases/download/videos-v1.0/<file>.mp4`), referenced in `animation.generated.json` (from `showcase:assets`; the short loops ship in `public/showcase/`). To add a film, upload it to that release, then add it to the asset script. `FIX_VIDEOS_NOW.md`, `VIDEO_DEPLOYMENT_GUIDE.md`, and `ALTERNATIVE_VIDEO_HOSTING.md` describe the hosting options that were considered.
- **Embeds:** Hackathons frames its live sites and Games frames itch.io's embeds (`<iframe>`). `next.config.ts` sets a permissive `Permissions-Policy` (sensors, XR) on every page for those embeds.

### Config notes

- `next.config.ts` sends `Cache-Control: public, max-age=31536000, immutable` on all routes, but only in production. Before that fix, browsers cached dev chunks too, so a browser that visited before then may still show old JS: hard-reload (Cmd+Shift+R).
- **Link previews:** `src/app/opengraph-image.jpg` and `twitter-image.jpg` (+ `.alt.txt`) are a 1200×630 screenshot of the hero with the turtle painting (Snorkeling Hawaii) finished. Next turns them into the `og:image` / `twitter:image` tags, and on Vercel it fills in the production URL itself. Without them, iMessage picked the first `<video>` on the page (VRShop's loop) as the preview.
- **Lite mode (`src/lib/perf.ts`):** on machines that can't keep up, the heaviest effects ease off: the Animation models stop auto-rotating, Earth Blaze (already pixel art, so cheap) idles at 20 fps, and the film grain holds still. It starts lite on software rendering, ≤2 GB memory or ≤2 cores, and otherwise drops to lite if two 1 s windows in a row struggle: the median frame over 40 ms, or over 22 ms and 1.5× the window's fast frames (dropped frames; a browser steadily capped at 30 fps, like Chrome's Energy Saver or a covered window, doesn't count). It never climbs back. It sets `html[data-perf]` for CSS; components read `usePerfLite()`. `?perf=lite` / `?perf=full` forces one. Measure on a Mac that's charged: at low battery macOS throttles everything and the numbers mean nothing. Test weak machines with Chromium flags `--use-angle=swiftshader --enable-unsafe-swiftshader --disable-gpu-compositing`, a 2× screen and CPU throttling; headless on the real GPU gives unreliable frame rates.
- **Favicon:** `src/app/icon.svg` ("AS" in Poppins 800, outlined to paths, in a blue-to-purple gradient (Paintwise's colours) on `#0b0b0b`), with `apple-icon.png` (180×180, square; iOS rounds it) and `favicon.ico` (16/32/48) rendered from it. Next adds the tags itself.
- Don't run `next build` while `next dev` is running: they share `.next` and the dev server breaks until it is restarted.
- `three` (with `@types/three`) is a direct dependency, for Animation's models only (`stumpScene.ts`, loaded on demand).
